# Dateless Workouts with user-owned Placements

The imported file declares Workouts as an ordered list with advisory `suggested_days`
and no start date; the calendar is built afterwards from individual user-owned
Placements, generated by the import wizard and freely movable thereafter.

## Considered Options

The PRD originally keyed Workouts by weekday (`monday:`) with a routine `start_date`,
making the weekday the Workout's structural identity. Recurrence rules ("Pull every
Monday") were the other candidate for the schedule itself.

Weekday keys cannot represent the same Workout trained twice a week, a rotation of
more Workouts than there are training days, or two Workouts in one day — and they make
the everyday act of moving Monday's session to Tuesday a mutation of the programme
rather than of the calendar. Recurrence was rejected because the primary user behaviour
is *moving individual sessions*, which is precisely what recurrence models worst: every
move becomes an exception to a pattern.

## Consequences

`scheduled` and `skipped` disappear as stored states. A Placement whose date has passed
with no Session is *missed*, derived from the absence of a Session — there is no
background job and no state to reconcile. Placements are generated in bulk, bounded by
the Routine's `weeks`, so the calendar visibly runs out at the end of a programme.
